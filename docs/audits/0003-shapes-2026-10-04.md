# Shape audit, 2026-10-04

The classifier audit of [ADR 0003](../decisions/0003-statement-ui.md) §10 (step 4), run to settle the thresholds of §3 (0003 Q1).

- **Sample:** 50,000 Wikidata items drawn uniformly at random from the items that existed on 2026-10-04, by `tools/wikidata-sample.py`. Seed 1791138573, newest item Q141640901, 58,350 IDs tried. Every property is included. The sample is kept out of git in `docs/api/snapshots/big/`.
- **Classifier:** `scatter-wikibase-shape` at the ADR's thresholds, with Wikidata's roles (P585, P580, P582, P2241, P248).
- **Reproduce:** `cargo run --release -p scatter-wikibase-shape --example audit -- docs/api/snapshots/big/wikidata-20261004-sample-50000.json.gz`.
- **24 items were not classified.** Their statements use lexeme senses and forms (`L1026331-S1`, `L252247-F2`), which the model's ID parser does not accept yet. This is a gap in `scatter-wikibase-model`, not the classifier, and it would also refuse those items on a Wikidata mirror.

## What the numbers say

1. **Most groups are one value.** 90.3% of groups (61% of statements) are Single. Of the 46,662 groups with two or more values, Table, Chips and List take about a third each. Timeline (1.2%) and Series (0.6%) are rare in a uniform sample, which is mostly scholarly articles and astronomical objects. They matter on the pages people read most: people's employers, positions and education, and places' populations.
2. **Each coverage threshold sits in a valley.**
   - Timeline: 55% of groups with any start time have full coverage, and a second peak sits at 0.5–0.6. That peak is two-value groups where only one value has a start time. 0.8 keeps those out; 0.5 would add 368 timelines with an undated row.
   - Series: 96% of quantity groups with a point in time cover every value, so the coverage threshold barely matters (0.5 to 0.8 give the same 261 groups).
   - Table: 85% of candidate groups have a key on every value, and 0.8 sits above the 0.6–0.7 bump.
3. **The minimum sizes are the real levers.**
   - Table: lowering `table_min` from 3 to 2 turns 6,926 two-value Lists into Tables, and raising it to 4 or 5 does the reverse on a similar scale.
   - Series: `series_min` 3 adds 56 series, and 2 adds 313. A two-point line chart says little.
4. **Tables are mostly one column, and that column is mostly an ordinal.** 92% of tables have one column. The top cases are scholarly author lists: `P2093` author name string (8,960) and `P50` author (567), each by `P1545` series ordinal. Then come apparent magnitude by filter (`P1215` × `P1227`) and catalogue codes by catalogue (`P528` × `P972`). A one-column ordinal table reads better as a numbered list. That would need a `series-ordinal` role, which 0003 §7 does not have.
5. **The Matrix view is uncommon:** 5.6% of tables qualify.
6. **Folds and footnotes do real work.**
   - 0.4% of groups exceed 25 values, mostly `P2860` cites work and author lists.
   - 52% of multi-value groups share one reference across every value ("Cited by all N").
   - 26.7% of current values have no source.
   - Best values appear in 0.5% of groups, deprecated values in 0.9%.

## Recommendation

- **Keep every threshold as it is:** 0.8 for Timeline, Series and Table; 0.5 for columns; `table_min` 3; `series_min` 4; 12 distinct values for the Matrix; 25 values before folding. Each threshold sits in a low-density region, so the shapes are stable against small changes in the data.
- **Consider a `series-ordinal` role** (Wikidata P1545). A Table whose only column is that role would render as a numbered list. This changes no shape, only how one kind of Table is drawn.
- **Support lexeme sense and form IDs** in `scatter-wikibase-model` and the provider grammar, as a separate fix.
